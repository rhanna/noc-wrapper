# Architecture Tracking

Keep `docs/architecture/` up to date as the implemented system changes.

Start with `docs/architecture/overview.md`. Create subfiles as needed for distinct layers, design patterns and major components.

Only create architecture subfiles when there is enough implemented detail to justify them.

Update architecture docs when adding, removing, renaming, or significantly changing logic, design, architecture, external contracts and any decisions made along the way that would be helpful for a developer or an agent to know when picking up the project without any prior knowledge of the codebase.

Architecture docs should describe what is currently implemented, not future plans.

Keep entries concise and factual.
